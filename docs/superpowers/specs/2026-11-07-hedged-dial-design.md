# 延迟启动备用上游连接（hedged dial）设计

日期：2026-11-07　状态：已按对话中选定的方案执行

## 意图

`dial()` 目前对同一 DC 的两个 KWS 域名（`kwsN` / `kwsN-1`）串行尝试，首选卡住时要等满 7.5 s 超时才轮到备用。
目标是把"首选明显慢"这类卡顿缩短到一个固定的等待阈值，而不是追求"绝对最快的服务器"。

## 目标 / 非目标 / 反目标

- 目标：首选在 `hedge` 毫秒内未建连成功 → 启动备用；首选在此之前失败 → 立即启动备用；最先通过校验的连接胜出，另一个被取消或关闭。
- 非目标：跨 DC 选择、在线换线、吞吐/RTT 测速、客户端侧服务器选择。
- 反目标（出现即失败）：业务数据或 obfuscation header 发给未胜出的连接；取消落选者时误关胜出者；留下未关闭的连接、计时器或缓冲计数。

## 约束

- 候选只在 `hosts(dc, media)` 现有的两个域名之间，顺序不变。
- 保留现有全部握手校验：HTTPS、101、`binary` 子协议、无扩展。
- 竞争只到 WebSocket 建连阶段；`start()` 之后的流程不变。
- 单文件、无依赖；Workers 的 WebSocket 需先 `accept()` 再 `close()`。

## 方案比较

| 方案 | 取舍 | 结论 |
|---|---|---|
| 保持串行 | 简单；首选卡住时等 7.5 s | 现状 |
| 每次立刻并发两个 | 最快，但每条 lane 常态产生两次上游握手 | 否决：上游压力翻倍 |
| **延迟启动备用** | 常态只有一次握手；首选慢时才竞速 | **选定** |

## 已决定的做法

- `connect()` 只负责建连 + 校验，返回**未 accept** 的 WebSocket；不再在内部创建 `mkWire`。
- `dial()` 持有每个候选自己的 `AbortController`，再统一挂到 stream 的 `signal` 上；胜出者才包成 `mkWire(ws, signal, onOverflow)`，落选者 `accept(); close(1000)`。
- 迟到的候选（dial 已返回或已失败后才建连成功）同样被关闭。
- `CFG.hedgeMs` 默认 1500 ms；可用环境变量 `DIAL_HEDGE_MS` 覆盖，范围 `0..7500`。`0` = 立即并发；`7500` = 等同旧的串行行为。
- 该值从 `mkCfg` 经 `mkSession` → `mkStream` → `dial` 传递；`mkCfg` 的缓存键包含该字段。
